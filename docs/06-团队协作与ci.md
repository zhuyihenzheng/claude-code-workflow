# 06 · 团队协作与 CI

## 1. 配置就是团队代码

`AGENTS.md`、`CLAUDE.md`、Copilot 指令、settings、hooks、rules、agents、skills 与 MCP 配置走正常评审。hooks 可直接运行命令，修改它们与改 CI 一样需要审查。个人设置、真实 token 与生产连接不入库。

新成员先跑通人工构建/测试，再启用 AI 工作流。接入顺序见[模板说明](../templates/README.md)。

## 2. GitHub 集成分清用途

| 入口 | 用途 | 模板 |
|---|---|---|
| GitHub App + Action 的 `@claude` | 根据评论请求答疑或改代码 | [claude.yml](../templates/project/.github/workflows/claude.yml) |
| Action 自动 PR 评审 | 事件触发、显式 prompt，输出到 Actions 日志 | [claude-review.yml.example](../templates/project/.github/workflows/claude-review.yml.example)，按需改名启用 |
| 托管 Code Review 产品 | 服务侧自动评审 | 按产品可用性单独配置，不等同上述 workflow |

交互模板安装 App、配置 `ANTHROPIC_API_KEY`，保留 `id-token: write` 供默认 App 认证，并同时配置 job 与 action 的 `actions: read`。自动评审示例使用显式只读 `github_token` / `GH_TOKEN`，无需 App/OIDC；仍需模型凭据，且先用 gh 验证 PR 可读，读取失败即退出。订阅 token 对应另一个 input：`claude_code_oauth_token`。详细步骤与权限以[官方 Actions 文档](https://code.claude.com/docs/en/github-actions)为准。

Action 默认检查触发者写权限并拒绝未允许的 bot。本模板不放宽这些检查。自动评审默认跳过 fork PR、草稿与 bot；检出可信 base，Read/Grep/Glob 仅供 base 上下文；以 diff 新增侧 hunk 定位 HEAD 行号，上下文不足明确报告，不执行 PR head 的代码。不要为让 fork 获得 secrets 切到危险的 `pull_request_target` 执行模式。

只取消 `pull_request` 事件注释还不够：job 的 `if` 必须接受 PR 事件，并提供 automation `prompt`。本仓库用独立模板避免两种模式混淆。

## 3. 独立评审与合并标准

- 作者负责提交，AI 代码与人工代码使用相同标准。
- 只读 reviewer 输入必须包含基准提交、完整 diff（暂存/未暂存/新文件）、验收条件与实际测试结果；它没有 Bash，不能自己执行 git diff。
- PR 带验证证据；支付、认证、迁移与页面大改重点人审。
- 业务 CI 执行构建、单测/集成测试、页面断言和迁移校验，并用分支保护设置为 required checks。Stop hook 不是 required check，编译通过不等于测试通过。
- 本仓库的 [Validate templates](../.github/workflows/validate.yml) 只验证手册模板，不替业务仓库做 Maven/数据库/E2E 验收。它在 PR 和 main push 上运行 Linux/macOS/Windows 矩阵，Windows 跳过 POSIX 参考 hook 测试；模板默认不启用任何 hooks。功能分支只触发 PR 矩阵。

## 4. 成本与凭据

模板设置每次任务的轮次、美元预算与 workflow 超时；自动评审还按 PR 取消过时运行。它们是局部限额，不代替组织支出控制，也不代表固定账单。

凭据仅用于需要的任务；App token 的权限还由安装授权决定，不能把 workflow 中的只读 `GITHUB_TOKEN` 权限当成所有 token 的权限。对外部插件、MCP、mods 与 hooks 分别核对来源、更新机制、访问范围和退出方法。

## 5. 修复后交给 Claude 复审

先把修复推送到同一 PR，再逐条回复原 review thread，写清提交、行为变化、验证和仍未覆盖的范围。PR 总结附复审入口；保留线程供 reviewer 确认，不把作者自述当成复审结论。

本仓库根目录当前只启用了模板验证 CI，`templates/project/` 下的 Claude workflows 是供其他项目复制的模板。发 PR 评论或写 `@claude` 并不保证启动 Claude。可将以下指令交给有 GitHub 访问能力的 Claude Code：

```text
请复审 https://github.com/zhuyihenzheng/claude-code-workflow/pull/1 的最新 HEAD。
先核对当前 HEAD SHA，再读取原来的 10 条 inline review、对应修复回复和 docs/10-PR指摘对应.md。
对比上次评审提交 5bfff3001c21374f05f32155a6066d5936c9aa3a 与最新 HEAD，
并结合完整 PR diff 检查回归；逐项给出已修复/仍有问题/证据不足及当前文件行号。
区分本地测试、远端 CI 和未执行的真实集成验证；不要修改或合并代码。
```

已配置交互 Action 的目标仓库可以在评论中用 `@claude` 加上述要求触发；先确认 workflow 已启用和凭据有效。自动评审示例启用后在 `synchronize` 时运行，结果仍在 Actions 日志，不会自动回复原线程。

## 6. Copilot 与 Claude Code 共存 / 多系统推广

以下是团队分工建议，不是工具能力边界：

| 工具 | 谁使用 | 优先承担的工作 |
|---|---|---|
| GitHub Copilot | 全员，在各自 IDE 中使用 | 补全、局部小修改；仍需理解代码、执行测试并正常评审 |
| Claude Code | TL 先试点，验证后按任务扩大使用 | 跨文件任务、影响分析、SPEC 更新、提交前 review 预检；结论附实际验证证据 |

多个 Spring Boot 管理系统共享一份规则结构：

- 根目录 [AGENTS.md](../templates/project/AGENTS.md) 是项目规则的唯一事实来源。“团队共通规则”原样复制到各系统，变更统一评审后同步；“本系统固有信息”填写 JSP / HTMX / 两者并用、JDK/Spring Boot/数据库版本、构建与启动命令、系统易错点，不削弱共通规则。
- [CLAUDE.md](../templates/project/CLAUDE.md) 首行 `@AGENTS.md` 导入共通内容，仅追加 Claude Code 配置入口；不要再维护第二份构建/代码规范。导入行为见 [Claude Code 官方文档](https://code.claude.com/docs/en/memory#import-additional-files)。
- [copilot-instructions.md](../templates/project/.github/copilot-instructions.md) 引用 AGENTS.md 并保留安全、分层、验证、JSP/HTMX 必守摘要，便于仅加载本文件的入口使用。各 Copilot 入口（包括 code review）是否同时读取 AGENTS.md、支持何种路径指令取决于版本与入口，以 GitHub 官方文档为准，见[仓库自定义指令](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions)。不能假定写了文件就所有入口自动生效。
- 路径细则只在 `.claude/rules/` 编辑，通过 [sync_rules.py](../scripts/sync_rules.py) 生成 `.github/instructions/`，正文与 glob 保持一致；复制到业务仓库后运行 `python3 scripts/sync_rules.py .`，CI 运行 `python3 scripts/sync_rules.py . --check`。Windows 用 `py` / `python`。AGENTS.md 改动时人工核对 Copilot 摘要，不能让摘要形成独立规则。

推广先选一个 HTMX 系统，由 TL 用真实小任务验证片段替换、校验失败回填、CSRF/会话失效和截图证据，再让全员使用 Copilot 做小改。稳定后推广到 JSP 系统，填写本系统视图路径、外部 Tomcat/WAR 部署差异并验证 JSP/EL 渲染；遗留页面保持手术式修改。每套系统先跑通 Maven Wrapper、测试和浏览器验收，再记录当前 IDE/扩展/CLI 版本与实际指令加载情况；工具行为无法在本仓库确认的部分，以官方文档为准并在目标环境验收。

不要给 AI 客户资料、生产数据、生产库连接、密钥/token、凭据文件或含这些内容的日志/截图/附件；不用真实数据做演示。使用合成数据，必要上下文先脱敏并人工核对；权限配置与提示词不能替代组织的数据管理和访问控制。
