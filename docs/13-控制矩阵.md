# 13 · 控制矩阵

一条规则只写在提示词里，等于没有保证。本页把模板的每条要求拆成四问：**写在哪**（指令）、**谁拦**（强制）、**谁证明**（验证）、**还缺什么**。改模板或评审导入方案时，先看这张表里对应的行。

四层的分工：

- **指令**：AGENTS.md、路径规则、skill。告诉模型该怎么做，模型可能不照做。
- **强制**：权限规则、管理员下发的 managed settings、沙箱。在工具调用层面拦截，但权限规则只匹配命令文本。
- **验证**：CI 与分支保护、评审子代理、人审。事后判定，不依赖会话里的自述。
- **导入检查**：`install.py doctor`。确认上面三层在导入方项目里真的就位。

## 矩阵

| 要求 | 指令 | 强制 | 验证 | 缺口 |
|---|---|---|---|---|
| 用 Maven Wrapper，不用系统 `mvn` | AGENTS.md | allow 只列 `mvnw` 的精确命令，系统 `mvn` 会询问 | CI 用 `./mvnw` | 询问不等于拒绝，人可以放行 |
| 后端改动要有通过的测试 | AGENTS.md、`spring-endpoint` | 无 | [CI 示例](../templates/project/.github/workflows/ci.yml.example)的 `./mvnw -B verify` + 分支保护 | CI 示例需导入方自己启用 |
| 页面改动要在真实浏览器里验证 | AGENTS.md、`rules/jsp.md`、`rules/htmx.md`、`change-flow` | 无 | 导入[画面试验](14-改修流程与画面试验.md)后：CI 运行 `cases.mjs`，产出 JUnit 与试验结果，与基准不符即失败。未导入时只有评审子代理与人审 | 画面试验是可选组件；不导入的项目，这一行仍然没有会话外的证明 |
| 画面试验的期待值来自设计书，不迁就实现 | `change-flow`、框架的用例规范 | `--update-baseline` / `--update-visual` deny；`baseline.json` 编辑 ask | `観点カバレッジ.md` 列出没有设计书依据的期待值；人审 | 覆盖率只按文字匹配，业务规则与边界值仍靠人看 |
| 不把画面截图发给模型 | [画面试验的 README](../templates/project/screen-tests/README.md) | AI 引擎与 `--heal` / `--ai-assert` 为 ask；`report.html` 禁止读取 | — | ask 由人判断；发往哪个模型由 `.env` 决定 |
| Excel 只按变更指示修改 | AGENTS.md、`change-flow` | xlsx 的 Read deny；`xlsx_patch.py` 不在 allow 里，每次确认 | `xlsx_patch.py` 自检；`diff --expect` 核对人的修改 | 结构性修改（插入行等）只能人做 |
| 不读 `.env` 与凭据 | AGENTS.md | Read / Edit deny | `doctor` 检查 deny 规则存在、`.env` 未入库 | deny 管不住任意脚本读文件；文件名规则只是猜测 |
| 不直接读 Excel 设计书 | AGENTS.md、CLAUDE.md | Read deny `.xlsx` / `.xlsm` | CI 可选的 `xlsx2ai.py --check` | 同上 |
| 不改已合并的迁移 | AGENTS.md | Edit 为 ask | 迁移工具校验 + CI | ask 由人判断 |
| 不 force push | — | Bash deny（常见写法） | 远端分支保护 | 分支保护需在仓库侧配置，模板无法代办 |
| 不跳过权限确认 | — | managed settings 的 `permissions.disableBypassPermissionsMode`（模板未设置；`company` 分支的项目设置带此项） | — | 只有管理员下发才算强制，项目设置开发者可改 |
| 不把客户数据交给 AI | AGENTS.md | 无 | 无 | **只有指令**。属于组织层面的控制：合同、接入方式、DLP、培训 |
| 不向任意地址发数据 | — | managed settings 的沙箱网络白名单 | — | 依赖管理员下发；模板只给示例 |
| 只用批准的 MCP、插件、mod | [工具箱](05-工具箱.md) | managed settings 的 MCP 白名单、市场锁定、内置守卫选项（示例见 `company` 分支） | `doctor` 提示远程 MCP 与未钉版本的 `npx` | 依赖管理员下发 |
| 路径规则与 Copilot 镜像一致 | — | — | `sync_rules.py --check`（CI 示例、`doctor`） | — |
| AGENTS.md 填完且不超长 | 模板里的 TODO | — | `doctor`：有 TODO 即失败，150 行以上告警 | — |
| 评审独立于实现 | CLAUDE.md、`spring-endpoint` | 评审子代理只有 Read / Grep / Glob | 人审 | 子代理是否被调用无法强制 |
| GitHub 自动化不越权 | workflow 模板里的注释 | workflow 的 `permissions`、默认不安装 | actionlint | App 的安装授权在仓库外 |

## 怎么用这张表

- **加一条规则时**：先填这一行。四列里只有“指令”有内容的规则，要么找到强制或验证的落点，要么在“缺口”里写明它只是约定。
- **评审导入方案时**：逐行确认“强制”和“验证”列在目标环境里是真的生效，而不是文件存在。
- **出了问题时**：看问题对应的行缺的是哪一层，补那一层，不要只是把指令写得更重。

## 导入后的检查

```bash
python3 scripts/install.py doctor /path/to/your-project
```

只读，不改任何文件。有 `fail` 时退出码为 1，可以放进导入方的 CI。它检查的是配置是否就位，不能证明规则在会话里被遵守。
