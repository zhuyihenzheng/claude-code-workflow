# 07 · 避坑清单

以下是工程建议；不把社区经验泛化成所有模型、版本都适用的“官方禁令”。

| 坑 | 后果 | 对策 |
|---|---|---|
| 复制未经验证的 settings | JSON 能解析，但事件名/字段未必被接受 | `/doctor`、`/hooks`、官方配置文档与模板测试一起检查 |
| `formatter || true` | 缺插件、格式化失败都变成成功 | 先配置 formatter，失败要报告；避免每次编辑全库改写 |
| 误以为复制模板就会跑 Stop hook | 结束会话后没有编译证据 | 模板不启用任何 hooks；`verify-stop.py` 仅为可选 macOS/Linux/WSL 样例，用户自行添加注册（见[模板说明](../templates/README.md)）；Windows 需先改写；显式运行验证，CI 负责最终门禁 |
| `compile` 当全量验收 | 测试、集成、JSP 渲染问题漏掉 | 定向测试 + verify + 真实页面交互 |
| `Read(.env)` 当全局隔离 | 任意脚本/MCP 可有独立读取能力 | 明确工具权限边界，OS 沙箱与最小凭据配合 |
| deny 整个迁移目录 | 新迁移也创建不了 | 确认变更 + 迁移校验，区别已合并文件与新增文件 |
| HTMX 返回 422 却未配 swap | 错误片段收到但不显示 | 按版本配置 422 响应处理，并测试无效输入 |
| JSP 使用 `:: fragment` | 默认 JSP ViewResolver 无法解析 | 返回独立 JSP 片段视图 |
| HTML 转义用于所有上下文 | JS、CSS、URL 注入仍可能发生 | 按输出上下文处理，不在脚本内直接插入不可信 EL |
| 只读 reviewer 未拿到 diff | 审查不完整却声称通过 | 主代理提供基准、完整 diff、新文件与验证结果 |
| 只加 PR 事件但保留评论 if | 自动 review job 永远跳过 | 独立 workflow + PR 条件 + automation prompt |
| 公共 fork PR 要求 Secret | 认证失败或误引入危险触发方式 | 默认跳过 fork；不执行带 Secret 的不可信 PR 代码 |
| 过多扩展、重复框架 | 配置冲突、排查困难 | 最小集合，按任务测量效果与开销 |
| 混合不相关任务 | 上下文噪音增多 | 任务拆分，必要时新会话附完整需求与已验证事实 |
| 依赖可变的 `@latest` | 下次安装行为漂移 | 固定直接版本，更新后重新测试；更严格时锁传递依赖 |

## 版本与来源纪律

- 命令、模型、窗口大小、默认权限模式与插件可用性随版本/账号/平台变化。记录 `claude --version`，核对 `/help` 与官方对应说明。
- 是否归档看仓库真实状态；不因为旧文章里出现工具就判定它不能使用，也不因为 star 多就判定成熟。
- “省 55K token”“安全 A 级”“账单降低/提高 X%”等数字需要可复现方法和条件；本手册不把未核实数字作为选型依据。
- 回滚工具、AI review、提示词与 Stop hook 都不能替代版本控制、测试、人审和分支保护。
