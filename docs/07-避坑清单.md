# 07 · 避坑清单

## 官方明说"可以停止做"的事（2025 年攻略多已过时）

- 拼命手工管理上下文（1M 窗口 + 自动 compaction 之后不再是第一约束）；
- 给指令加 IMPORTANT / 全大写强调（对现行模型无效）；
- 为了"省上下文"而用 subagent（subagent 要重新收集上下文，未必省、未必快）；
- 指望 subagent 给出"更聪明"的答案（它的价值是隔离与并行）；
- `think hard / think harder` 等措辞（思考量用 `/effort` 与 `ultrathink` 控制）；
- 反复喊"继续、别偷懒"（问题在任务定义，不在态度）；
- 在 CLAUDE.md 里写架构与文件布局（模型读代码比你写文档快）。

## 高频翻车点（社区实测总结）

| 坑 | 症状 | 正解 |
|---|---|---|
| Kitchen sink 会话 | 一个会话里混十个不相关任务，上下文全是噪音 | 任务之间 `/clear`；侧问题用 `/btw` |
| 纠正兔子洞 | 同一问题纠正两轮以上越改越歪 | 纠正两次还不对就 `/clear` 重写 prompt（含新学到的信息） |
| 无限探索 | 让它"看看整个仓库"跑到天荒地老 | 探索要给范围与产出形式；大范围摸底派 Explore 子代理只回摘要 |
| 巨型 CLAUDE.md | 几百行全是架构说明与通用规范，关键命令被淹没 | <200 行；流程搬 skill、局部规则搬 rules + `paths:`；`/doctor prompt-audit` 定期审计 |
| MCP 泛滥 | 装十个 server，每个会话先烧掉几万 token 还互相干扰 | 起步 4 个（见 [05](05-工具箱.md)）；`/mcp` 关闲置；能用 CLI 的不用 MCP |
| 无验证回路 | "写完了"→ 人肉通读全部 diff，AI 产能被人审速度卡死 | 先建可判定 check（测试/构建/截图），再放它写；要求输出证据 |
| 一次性巨型 prompt | 把整个需求一口气倒给它，中途不可纠偏 | 先访谈出 SPEC → 新会话实施 → reviewer 对照 spec 复核 |
| 把希望当强制 | "请不要读 .env"写在 CLAUDE.md 里 | 红线落 permissions `deny` / hooks / 沙箱（见 [02](02-基础搭建.md)） |
| 别名版本漂移 | 云厂商上 `sonnet` 解析到旧版模型还不自知 | `/status` 核对实际版本；云上钉完整 model ID |
| 旧命令教程 | 照 2025 年博客找 `/cost` 等旧入口 | 成本看 `/usage`；命令与功能以 code.claude.com 现行文档为准 |

## 已归档 / 已过时的工具（照旧教程装会踩空）

- MCP 官方 reference servers 自 2025 年起陆续归档 13 个：**Postgres、SQLite、Puppeteer、Slack、GitHub、GitLab、Brave Search、Google Drive** 等，能力改由厂商官方 server 接管；
  - 数据库 → DBHub 或厂商版（Postgres 性能分析看 Postgres MCP Pro）；
  - 浏览器 → 微软 Playwright MCP；
  - GitHub → 官方 github-mcp-server 或 `gh` CLI；
- 原 "Claude Code SDK" 已改名 **Claude Agent SDK**，旧包名教程注意迁移页；
- 成本命令口径：旧 `/cost` 说法过时，现行是 `/usage`。

## 营销数字打折区

- **RTK 类 token 代理**：有独立基准（约 $1,500 规模实测）结论为账单并未下降，另一基准显示成本反而上升——不要按其宣传页决策；真要引入，先用 ccusage 做两周前后对照；
- **巨型技能全家桶**：整装可达约 27K token 常驻上下文，只拆取单项；
- **Star 数**：同一仓库不同目录站的快照可相差数万，本手册所有 star 数只作量级参考。
