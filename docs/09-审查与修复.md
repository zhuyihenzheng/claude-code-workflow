## 第七轮：用真实会话复盘的 skill

日期：2026-11-16。基准：第六轮合并后的 `main`。

新增仓库维护用的 skill [`workflow-retro`](../.claude/skills/workflow-retro/SKILL.md) 与度量脚本 `session_metrics.py`：统计导入方项目的 Claude Code 会话记录，回答“最后一次改代码之后，模板要求的检查有没有跑通”，再按时间线定位、归因，达到证据门槛才改模板。它不随模板安装到导入方项目。

| 项目 | 说明 | 验证 |
|---|---|---|
| 输出不含会话内容 | 只输出次数；命令只保留程序名与已知工具的子命令，skill 与子代理名只接受标识符 | `test_output_never_contains_transcript_text`、`test_command_heads_carry_no_arguments_paths_or_heredoc_bodies` |
| 失败或跳过的检查不算验证 | 按 `tool_use_id` 关联结果，报错的不计；`-DskipTests` 计为编译 | `test_failed_or_skipped_checks_do_not_verify` |
| 子代理里跑的检查要算 | 合并 `<会话>/subagents/*.jsonl`，按时间排序 | `test_checks_run_by_a_subagent_count` |
| 带路径的 wrapper 要认得 | `./sub/mvnw`、`..\mvnw.cmd` | `test_wrapper_called_through_a_path_counts_and_system_mvn_is_flagged` |

试跑：在一个导入方项目的 23 个会话上运行，并对两个标为未验证的会话实际执行了 skill 的第 2–3 步。一个确认为页面改动后没有浏览器验证；另一个是脚本误判（wrapper 带路径），已修并补测试，归因表因此增加“度量误判”一类。样本不足，未据此修改任何模板规则。

已知限制：用自定义启动命令或其他测试工具跑的检查仍认不出，会被记为未验证；指标是代理，结论要读对应会话才能下。`--excerpt` 输出会话原文，仅供本机查看。

## 第八轮：token 开销排查

日期：2026-11-16。方法：统计一个导入方项目 23 个会话里各类工具结果的体积，并测量模板常驻上下文的大小。

| 排查项 | 结果 |
|---|---|
| 模板常驻上下文 | `AGENTS.md` 约 3,700 字符、`CLAUDE.md` 约 480 字符；路径规则各约 1,000 字符，只在处理匹配文件时加载。未发现需要削减的内容 |
| Maven 输出 | 假设“allow 的是不带 `-q` 的命令，会把完整构建日志灌进上下文”不成立：44 次 Maven 调用全部带 `-q` 并重定向到文件，平均每次返回不到 1,000 字符 |
| 评审子代理的输入 | 假设“完整 diff 被主会话复述一遍”不成立：9 次调用的提示词都在 2,100 字符以内，diff 以文件路径传递 |
| 图片 | **工具结果里体积最大的一类**：读回图片 27 次，另有浏览器 MCP 直接返回的截图 8 次；其中 26 次读图和全部 8 次截图集中在同一个会话 |

处理：在 `rules/jsp.md` 与 `rules/htmx.md` 的验证条目里补一句——合否由断言判定，截图是给人看的证据，除非断言判断不了外观，否则不读回保存的图片。在已有条目上追加，没有新增条目。

同时给 `session_metrics.py` 增加 `images read back` 与 `screenshots` 两个计数，下次复盘可以直接对比。

这是**假设，待下次复盘验证**：读图集中在一个会话，没有达到“两个会话同一原因”的门槛；体积按 base64 字符统计，不等于图片实际计入的 token 数，只能说明图片是最大的一类。未改 `AGENTS.md`。
