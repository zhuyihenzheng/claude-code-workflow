# 05 · 工具箱：MCP / Skills / 插件 / Mods

选型总原则：**每个扩展都收"上下文税"**——MCP 的工具定义、插件的常驻部分、技能的描述都占每个会话的上下文。社区测算 5 个常用 MCP server 约 58 个工具、约 55K token。所以：起步最小集、按需再加、定期用 `/context` 与 `/usage` 审计谁在吃上下文（占比 >10% 会被标出）。Star 数为 2026 年 10 月各来源快照，不同来源差异很大，**只作采用度量级信号**。

## 1. MCP：起步只装 4 个

| MCP | 用途 | 对本项目 | 来源 |
|---|---|---|---|
| **Context7** ★起步 | 按版本拉取当前库文档与示例，治"用训练数据里的旧 API 写代码" | Spring Boot / Spring Security / HTMX 查当前版本文档，目录明确覆盖 Spring Boot | github.com/upstash/context7（约 62.8k★) |
| **Playwright** ★起步 | 微软官方浏览器自动化：导航/点击/填表/截图/读 console | **本项目关键**：HTMX swap 与 JSP 渲染只能在真实浏览器验 | github.com/microsoft/playwright-mcp（约 37.9k★) |
| **DBHub** ★起步 | Bytebase 的通用数据库 MCP，一个 server 连 Postgres/MySQL 等，工具少省上下文；Claude Code 官方 MCP 文档的数据库示例 | 只读账号连开发/测试库 | github.com/bytebase/dbhub（约 3.3–3.6k★，安全扫描 A 级） |
| **GitHub** ★起步（二选一） | 官方 GitHub server：repo/issue/PR/Actions | 与 `gh` CLI 二选一——官方明说 **`gh` 更省上下文**，团队已熟 gh 的话可以不装 | github.com/github/github-mcp-server（约 33.4k★) |

按需再考虑：
- **Chrome DevTools MCP**（Google 官方，约 47–53k★)：查 HTMX 请求头、网络、性能 trace 时与 Playwright 互补；
- **Serena**：官方 jdtls-lsp 插件已覆盖其核心卖点（符号导航+诊断），只剩跨文件符号级编辑的增量，且 Java 启动慢——先不上（见 [04](04-java-spring-htmx-jsp.md)）；
- **Sentry MCP**（厂商官方版）：项目在用 Sentry 时，对线上 bug 修复回路有价值；注意凭据作用域；
- **Fetch**（官方 reference）：HTML→Markdown 清洗比内置 WebFetch 干净，常读在线文档页时可装，否则不必。

明确不装：
- **Sequential Thinking**：已被 effort 等级、Plan Mode、`/goal` 覆盖，社区共识是平时关掉省 token，疑难会话临时开；
- **Filesystem / Git / Memory reference servers**：与 Claude Code 内置工具/Auto memory 完全重复，纯付上下文税；
- **已归档的 reference servers**（`@modelcontextprotocol/server-postgres`、`server-puppeteer` 等）：2025 年旧教程的重灾区，见 [07](07-避坑清单.md)。

配置纪律：项目级配置写 `.mcp.json` 入库；密钥一律 `${ENV_VAR}` 引用；闲置 server 用 `/mcp` 关掉。

## 2. Skills 与技能框架

- **官方 anthropics/skills**（约 177–184k★)：只装两个——`webapp-testing`（驱动 Playwright 验页面，本项目回路的另一半）、参考 `skill-creator` 写自己的技能；
- **方法论框架二选一，不要叠装**：
  - **Superpowers**（obra，约 279–301k★，已进官方 marketplace)：brainstorm→spec→plan→TDD 铁律→子代理实施→任务间 review 的全套纪律。与 JUnit 天然契合；仪式偏重，适合新功能，团队可先试点或只摘 TDD/debugging 几个技能；
  - **Matt Pocock skills**（约 250–307k★)：小而可组合：`/grill-me`（动手前访谈）、`/tdd` 等；理念与官方"先访谈出 spec"一致，示例语境偏 TS，需改写后落地；
  - 备选 Addy Osmani agent-skills（按 /spec /plan /build /test /review /ship 组织）；
- **项目自研 skill 才是长期资产**：把团队反复做的多步流程（如"新增一个 Spring 接口并配齐测试与页面片段"）写成 `.claude/skills/<name>/SKILL.md`。内置 `/run-skill-generator` 能把本项目的启动/验证方法自动记录成项目 skill。模板见 [templates/project/.claude/skills/](../templates/project/.claude/skills/)。
- 巨型全家桶包（如 ECC 一类）整装约 27K token 常驻上下文——**只拆取单个技能，不整装**。

## 3. 官方插件（claude-plugins-official)

首次交互启动时自动添加官方 marketplace。Java 团队推荐：

| 插件 | 用途 |
|---|---|
| `jdtls-lsp` | Java 代码智能：符号导航 + 编辑后诊断（需自装 jdtls 二进制） |
| `code-review` | PR/变更评审（常驻成本极低） |
| `commit-commands` | 规范化提交流程 |
| `security-guidance` | 安全向导 |
| `code-modernization` | 遗留代码现代化——与 JSP 老页面治理相关 |
| `feature-dev` / `claude-md-management` / `hookify` | 特性开发流程 / CLAUDE.md 维护 / 快速写 hook，按需 |

装法：`/plugin install <name>@claude-plugins-official`；社区 marketplace `claude-community` 需手动 `/plugin marketplace add anthropics/claude-plugins-community` 后再审慎挑选。

## 4. 状态栏与用量工具

- **claude-hud**（约 28.6k★，插件形态）：状态栏显示上下文用量、模型、成本等——上下文焦虑的解药是可视化；
- **ccusage**（约 19.1k★)：按天/会话统计用量与成本，周复盘用它 + 内置 `/usage` 交叉看；（注意：旧教程里的 `/cost` 命令在现行文档中已是 `/usage`）；
- 并行开发先用原生 `claude --worktree`，Worktrunk / Claude Squad 等第三方 worktree 工具等原生不够用再说。

## 5. Mods：先只看，不装第三方的

Mods 是 2026-10-01（v2.1.287）才发布的新机制：JS/TS 函数**在 Claude Code 进程内**运行，可拦截/改写工具调用与 prompt、绘制自定义 UI。

⚠️ 安全边界（官方自己警告）：mods **不经过沙箱**，能读到包括 API key 在内的进程内信息。因此团队策略：
- 早期只用官方内置 mod（如 token 用量可视化一类）；
- 第三方 mod 一律先过代码审查再装，来源不明的坚决不装；
- 企业管控可用 `allowManagedModsOnly` 只允许组织下发的 mod。
