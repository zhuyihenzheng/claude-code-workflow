# プロジェクト知識の書き戻し

次の作業で同じ調査を繰り返さず、依頼の言葉を正しいコードに結び付けるために、今回の作業で確かめた事実を `docs/knowledge/` に残す。書式は `docs/knowledge/README.md` に従う。

## 1. 書き戻す候補を挙げる

今回の作業を振り返り、次に当てはまるものを挙げる。

- **用語**：依頼や設計書の言葉が、画面の項目名・クラス名・テーブル名と違っていたもの（`glossary.md`）。
- **場所**：修正箇所を探すのに時間がかかったもの、機能 ID に対して複数のファイル（画面、フラグメント、Controller、Mapper の XML、設計書、テスト）が関わっていたもの（`codemap.md`）。
- **注意点**：コードを読んだだけでは分からず、試して初めて分かったこと（例：共通レイアウトの都合で 422 を返す必要がある、同じ JSP を 2 つの画面が使っている）。

次は書かない：推測、作業の経過や感想、規約（`AGENTS.md`）、機械で止められる誤り（`correct` skill で guard・ArchUnit・PMD・テストにする）、利用者から見た操作手順（`docs/feature-map/`）、顧客情報・認証情報。

## 2. 書く

- ファイルがなければ、README の書式で作成する。
- 1 事実 1 行で書き、パスはリポジトリのルートからの相対パスをコードスパンで書く。根拠のない記載はしない。
- 既存の記載と食い違う場合は、今回確かめた事実に置き換える。移動・削除されたファイルの記載は消す。
- `codemap.md` の見出しの機能 ID が機能マップにない場合は、先に `feature-map` skill で機能ファイルを作る。

## 3. 確認する

- `python scripts/knowledge_check.py` が終了コード 0 になることを確認する。NG は表示されたとおりに直す。
- 書き戻した内容を、変更したコードと同じ PR に含める。

## 報告

追加・更新・削除した記載（ファイルと見出し）と、`knowledge_check.py` の結果を報告する。書き戻すものがなかった場合は、その旨を報告する。
