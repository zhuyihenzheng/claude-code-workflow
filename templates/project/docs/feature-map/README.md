# 機能マップ

利用者から見た機能の一覧と、各機能を実際に動かして確認する手順である。人もエージェントも、画面と機能はここの名称と機能 ID で呼ぶ。作成と更新の手順は `.claude/skills/feature-map/SKILL.md` に記載している（Claude Code と GitHub Copilot はどちらも `feature-map` skill として読み込む）。

## 共通の前提

- アプリケーションは、AGENTS.md「本システム固有情報」の起動コマンドでローカルに起動する。共有環境や本番環境を操作しない。
- テストアカウントと初期データは合成データを使用する。実際の認証情報や顧客データを書かない。
- 証跡は `target/evidence/<機能ID>/` に保存する。PR には、実行したコマンドと結果、証跡の保存先（またはアップロードした画像）を記載する。

## 機能ファイルの書式

1 機能 1 ファイル、ファイル名は `<機能ID>-<英小文字の短い名前>.md` とする。冒頭に `# <機能ID> <機能名>` と、利用者から見た振る舞いを 1 段落で書き、次の 4 つの節をこの順で置く。

1. `## サブ機能`：`<機能ID>-<番号>` の ID と 1 行の説明。
2. `## 到達方法`：メニューからの経路、URL、必要なログイン状態と権限。入口が複数あればすべて書く。
3. `## 操作と確認`：先頭に「前提：」を書き、操作ごとに、実行するコマンドと、合格と判断できる利用者に見える結果を書く。
4. `## 注意点`：確認を無駄にしたり、誤って合格にしたりする落とし穴。

実装の詳細（クラス名、内部 API）は書かない。利用者の操作、変わりにくいセレクター、前提データ、コマンド、確認できる結果だけを書く。
